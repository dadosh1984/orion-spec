# Orion Implementation Plan – Steps 101‑120

**5️⃣ Cache Integration Across All Modules**
101. В `forge.handler` перед запуском `tdd start` проверять `track.load('forge:'+slug)`; если `DONE` → пропустить.
102. После успешного завершения задачи записывать `track.store('forge:'+slug,'DONE')`.
103. В `shield.handler` перед каждой проверкой (`lint`, `type`, `test`, `drift`, `security`) вызывать `track.load('shield:'+step)`; если `PASS` → пропустить.
104. После успешного выполнения шага сохранять `track.store('shield:'+step,'PASS')`.
105. В `scale.handler` (если будет) использовать кеш `track.load('scale:'+stage+':'+hash)` перед вызовом обработчика.
106. Добавить глобальный флаг `--no-cache` во все команды (`think`, `draft`, `forge`, `shield`, `scale`, `tdd`) – отключать любые обращения к кешу.
107. В `OrionTrack.prune` добавить авто‑удаление записей истёкшего TTL (из `orionTrack.json`).
108. В CI‑pipeline добавить шаг `node dist/cli/index.js track prune` перед сборкой.
109. Добавить unit‑тест `track.ttl.test.ts` – имитировать старый файл, проверять его удаление после `prune`.
110. Обновить `README.md` секцию **Cache (track)**: объяснить как `--no-cache` полезен для отладки.
111. Добавить в `src/cli/commands.ts` команду `track status` (вывод количества записей, размер, время последней очистки).
112. Добавить в `src/cli/commands.ts` команду `track clear` – полное удаление кеша (для чистых запусков).
113. В `src/cli/index.ts` зарегистрировать новые под‑команды `track status` и `track clear`.
114. Добавить метод `OrionTrack.getStats()` → `{count, size, lastPrune}` для UI (будущее).
115. Добавить в `docs/architecture.md` блок, показывающий связь `core ↔ track ↔ skills`.
116. В `src/utils/hash.ts` добавить функцию `hashFile(path)` (чтение и хеш). Полезно для кеша кода.
117. Добавить в `src/core/track.ts` метод `invalidate(keys:string[])` – удалять конкретные записи (используется в `forge` при изменении кода).
118. Добавить unit‑тест `track.invalidate.test.ts` – проверка, что после инвалидации `exists` возвращает false.
119. В `forge.handler` вызвать `track.invalidate(['shield:lint','shield:test'])` после каждой правки кода, чтобы guard‑checks пересчитались.
120. Обновить CI‑workflow: после `pnpm build` добавить `node dist/cli/index.js track prune`.
