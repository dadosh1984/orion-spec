# Spec: core

## Назначение
Провести глубокий честный аудит проекта Orion v0.46 и реализовать до 20
кардинальных улучшений по 5 фазам (A Windows-совместимость, B дубли и мёртвый
код, C user-friendly терминал, D производительность, E функциональность),
не повторяя уже реализованное, сохранив zero-зависимость и все гейты зелёными.

## Область
- В области: скриптовый рантайм (кросс-платформа), единый вывод, чистка дублей,
  асинхронность, единый конфиг, уроки, README.
- Вне области: инфраструктура CI, docker-песочница, сторонние интеграции.

## Критерии приёмки
- [c1] `orion run new <name>` на Windows создаёт и запускает скрипт без ручного `--node`,
      когда bash недоступен; при TTY даёт интерактивный выбор рантайма.
- [c2] `orion run schedule` на Windows и Unix сообщает честно о поддержке, не молча косячится.
- [c3] Дубли `humanBytes`/`formatBytes` сведены к одной функции; неиспользуемые экспорты удалены.
- [c4] Ни одна команда не выводит сырой `JSON.stringify` в терминал без флага `--json`.
- [c5] Опасные команды (delete/clean/archive) запрашивают подтверждение при TTY.
- [c6] `execSync` для запуска скриптов заменён на асинхронный `spawn`.
- [c7] Единый `~/.orion/config.json` + `orion config` читает/пишет runtime-настройки.
- [c8] `out`/`shield` умеют писать человекочитаемую Markdown-сводку в файл.
- [c9] `draft` применяет топ-уроки `lessons` к конкретному change автоматически.
- [c10] Все гейты зелёные: lint, tsc, 663 теста без регрессий.
