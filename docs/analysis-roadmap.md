## Часть 2. Найденные баги и слабые места (с доказательствами)

### Критичные / реально воспроизведённые

1. **`deriveTasks`: ложное срабатывание maintenance-плана.**
   Регекс `/\bupdate(?:d|s)?\b/` в `src/skills/draft/handler.ts` матчит слово «updates» в тексте *новой фичи* (не багфикса) → генерируется план RED→fix→verify вместо реальных задач. **Воспроизведено вживую** в этом проекте: изменение `user-adaptation-memory-profile` получило бессмысленный maintenance-план («Reproduce the failure…»), tasks.md пришлось переписывать вручную. Причина: действие и сущность не разделены — «обновить конвертер» и «файл с updates в описании» неразличимы.

2. **`shortSlug`: непредсказуемость слагов.**
   `shortSlug()` в `src/skills/forge/handler.ts` берёт первые 2–3 значимых слова из описания задачи. Спланированный слага ≠ фактического: в этой сессии `profile_topics` → `profile_topics_frequent`, `lesson_notify` → `lesson_notify_visible`, `profile_cli` → `profile_cli_view`. Автор должен угадывать слаги до forge — сниппеты приходится переименовывать (churn).

3. **Security-сканер shield флагает `process.env` в `src/tasks`.**
   `securityScan()` (`src/skills/shield/handler.ts:753`) паттерн `process\.env\.` → любой код задачи с чтением env получает **FAIL** guard'а. Пришлось обходить через `import { env as processEnv }`. Обход не документирован, для новичка это тупик.

4. **🧠-шум в захваченном выводе тестов shield.**
   Уведомления уроков пишутся в stderr; shield захватывает stdout+stderr прогона vitest → в `guard-report.md` появляется «[orion] 1 failing line(s): 🧠 orion lesson recorded — …» при **успешном** прогоне (видно в result.md изменения user-adaptation-memory-profile). Путает и людей, и агентов.

5. **Профиль: глаголы-мусор в Frequent topics.**
   `countTopics()` фильтрует стоп-слова, но не глаголы: в профиле реально оказались `сделай, почини` (видно в демо). Тематика должна собираться из существительных.

6. **Мусорные каталоги в репо:** `cwd/` (53K) и `.pytest_cache/` не в `.gitignore`.

### Архитектурные слабости

7. **Обучение только на ошибках.** Уроки записываются лишь при сбое; успешные паттерны (что сработало) не учат ничему. `lessons_learn` детектит пары failure→success, но не записывает успешный паттерн как знание.
8. **Шаблоны только на английском.** Профиль записывает `Language: ru`, но `src/core/templates.ts` генерирует артефакты только по-английски — язык не применяется.
9. **MCP-инструменты возвращают JSON-строки.** Из 20+ инструментов человекочитаем только `out` (исправлен ранее); остальные — `JSON.stringify`, агенты обязаны парсить.
10. **`prompts/list` и `resources/list` MCP пусты** — протокол позволяет отдавать шаблоны промптов и ресурсы, но ничего нет.
11. **Нет `orion list`** — посмотреть все изменения и их фазы можно только через `next` (одно изменение) или ls.
12. **Нет диагностики окружения** (`orion doctor`) — при сломанном node/pnpm/vitest пользователь получает непонятные ошибки.
13. **Нет архивации изменений из CLI** — changes/archived существует, но команды нет.
14. **`orion profile` только читает** — нет `--edit`/`--reset`.
15. **Плагины без npm-источника** — только локальная папка.
16. **Нет JSON Schema** для `orionTdd.json`, `policy.json`, `manifest.json` плагинов — IDE не подсказывает.
17. **Нет pre-commit / интеграции с CI как продукта** — shield запускается вручную.
18. **Кэш OrionTrack — много мелких файлов** — на 10k записей это тысячи файлов; бенчмарка нет.

## Часть 3. Функциональность и востребованность

**Сильные стороны (что уже есть и востребовано):**
- Полный детерминированный цикл think→draft→forge→shield→out без LLM-зависимостей на этапах draft;
- Самоисправление (уроки, selfCorrection-маршрут, toxic-loop stop, budget stop);
- Память пользователя (профиль v0.26), видимое обучение (🧠-уведомления);
- Zero-dependency runtime, работает на Node ≥ 22, CLI + MCP + веб-дашборд;
- Честность как принцип: идемпотентность, маркеры custom-шаблонов, «не придумываем done».

**Пробелы востребованности (что спросил бы пользователь-агент):**
- Нет языковой адаптации артефактов (профиль есть, применения нет);
- Нет простой обзорности: «что у меня в работе?» (list/stats);
- Нет визуализации обучения (дашборд не показывает уроки/профиль/кривую затрат);
- Нет ревью между forge и shield (агент пишет код → никто не проверяет до гейтов);
- Нет онбординга (init), диагностики (doctor), архивации;
- Экосистема плагинов/шаблонов без маркетплейс-механики;
- Нет позитивного обучения — только коррекция ошибок.
